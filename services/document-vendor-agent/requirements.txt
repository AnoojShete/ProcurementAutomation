# Docling: layout-aware PDF parsing (reading order, table structure) —
# used for every PDF (text-native or scanned; Docling OCRs scanned pages
# itself via its bundled RapidOCR engine), replacing plain pdfplumber for
# those. pdfplumber/pytesseract stay as the dependency-light fallback path
# if Docling fails to load or errors on a given file (see
# app/services/ocr.py). Runs fully local/offline — no document content
# leaves the machine.
#
# PaddleOCR/PaddlePaddle were evaluated for standalone image OCR and
# rejected: the native inference engine segfaults/aborts on every version
# pair tried (paddleocr 3.7.0+paddlepaddle 3.2.2, and the older
# 2.9.1+2.6.2 pairing) on both native arm64 and emulated amd64 in this
# Docker environment — three distinct crash signatures (SIGABRT in
# paddle_infer::Predictor, a PIR/oneDNN NotImplementedError, and a SIGSEGV
# in zlib's inflateReset2), none of them catchable from Python since
# they're C-level process aborts. pytesseract remains the image-OCR
# engine; see the finding written up for the team.
